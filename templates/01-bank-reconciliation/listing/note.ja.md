# 入金消込を n8n に任せて、人が見るのは確認が必要な分だけにする

## 毎月の消込

請求書払いで売上を回収していると、月初に入出金明細と請求一覧を並べ、1 件ずつ金額と振込名義を照らし合わせる作業が発生します。手数料が差し引かれた入金やまとめ払いが混ざると、そのたびに手が止まります。

私は決済代行会社で約 10 年、管理画面と加盟店サポートを担当していました。このテンプレートは「消込は人が見るべき分だけ人に渡す」という考えで設計し、曖昧なものは自動で確定しません。

## このテンプレートがやること

n8n 2.x のワークフローです。Google Sheets の請求一覧（`invoices`）を台帳にして、次の順に動きます。

- 取込：Google Drive の監視フォルダに置いた銀行 CSV（Shift_JIS／UTF-8 BOM）、または Gmail の入金通知メール（正規表現で解析）から入金を読みます。出金行は無視します。
- 正規化：振込名義のカナ表記のゆれ（全角半角、法人格の略記など）をそろえ、入金ごとに `txn_id` を作ります。
- 突合：名義と金額が一致すれば自動消込。手数料差引（既定 110〜880 円）、2〜3 件の合算、一部入金も規則で確定し、通知に理由を付けます。同額の請求が複数あって絞れない場合や該当請求がない場合は確定せず、候補を添えて人に渡します。
- シート更新：`invoices` の `status` / `paid_amount` などを更新し、すべての入金を `transactions` に記録します。通知より先に書きます。
- 通知：件数のサマリと、自動消込／要確認／候補複数／未消込の 4 区分の明細を、Slack・メール（Gmail）・LINE・Chatwork のうち設定したチャネルへ送ります。
- 再突合：毎朝 09:00（JST、変更可）に未消込の入金を再突合し、あとから登録した請求を拾います。

## 導入手順のダイジェスト

同梱の `SETUP.ja.md` は、n8n を初めて使う人が約 30 分で導入できることを目標にしています。要約すると 8 ステップです。

1. スプレッドシート作成。同梱の CSV テンプレートから `invoices` と `transactions` を作り、列名は変えない（5 分）。
2. Google 側の準備。OAuth クライアントを作り、n8n に Sheets / Drive / Gmail の Credential を登録する（10〜15 分）。
3. 通知先の準備。Slack・LINE・Chatwork のトークンを n8n の Credential に入れる（使うものだけ、3〜10 分）。
4. 取込。`error-handler.json` → `workflow.json` の順に Import from File で取り込み、各ノードで Credential を選ぶ。使わない通知ノードは本体と Error Workflow の両方で無効化する（5 分）。
5. `Config` の編集。シート ID、CSV の列の対応、メールの正規表現、通知先など、調整値はこの 1 ノードにまとまっている。Error Workflow 側の `Config` にも同じ通知設定を入れる（3〜5 分）。
6. トリガー 3 ノードに実値を入れる。監視フォルダ、Gmail の検索式、再突合の時刻は `Config` より先に動くため（2 分）。
7. 動作確認。同梱の架空 CSV を監視フォルダに置き、通知とシートの変化を期待値の表と見比べる。もう一度置いて全件 skip になることも確認する（5 分）。
8. 本番化。試運転データを消し、`invoices.payer_name_alias` に振込名義（カナ）を入れ、本体と Error Workflow の両方を Publish する（3 分）。

Code ノードの中身は編集しません。Credential の選択、トリガー 3 ノードの実値、Settings での Error Workflow 指定を除けば、編集するのは本体と Error Workflow の `Config` だけです（Google ドライブのアップロード時変換を OFF にする設定は `SETUP.ja.md` §1 を参照）。

## 動かしてみた結果

同梱の架空データ（請求 20 件、入金 11 件と出金 4 件の銀行 CSV）を初期状態で流したときの通知です（`tests/RESULTS.md` §5.1、実行 92 の `Build Notification` 出力。`tests/CASES.md` §3 の期待値と一致）。

```
【入金消込 2026-09-23】処理 11件｜自動消込 4｜要確認 3｜未消込 4

■ 要確認（金額のみ一致・手数料差引・合算で自動消込した分）
・2026-09-02 振込 ﾃｽﾄｺｳｷﾞﾖｳ(ﾕ ¥54,780 → INV-2026-002 （手数料 ¥220 差引）
・2026-09-04 振込 ｻﾄｳ ｹｲｺ ¥128,000 → INV-2026-004 （金額のみ一致・要確認）
・2026-09-05 振込 ｶ)ﾃｽﾄﾌﾞﾂｻﾝ ¥1,234,567 → INV-2026-005, INV-2026-006 （合算）

■ 候補複数（自動確定せず。候補から選んでください）
・2026-09-09 振込 ｵｵﾊﾞ ﾏｻｵ ¥44,000 → 候補: INV-2026-008(¥44,000), INV-2026-009(¥44,000)
```

このあとに「未消込」3 件と「自動消込」4 件（一部入金は残額付き）が続きます。要確認の 3 件はシートを更新したうえで理由付きで列挙され、候補複数と未消込は `invoices` を変えず、`transactions` に `ambiguous` / `unmatched` として候補付きで記録されます。

検証は作者のセルフホスト n8n 2.40.5 で 2026-09-23 に行いました。Code ノード 8 本の単体テスト 10 スイートが合格し、受け入れテスト R01〜R23 は 22 ケース PASS、1 ケースは定義上対象なし、FAIL 0 でした。同じ CSV・同じメールの 2 回投入、再突合の 2 回連続で書込みが発生しないことも確認しています。

ただし、Google Sheets / Drive / Gmail の実 API は作者環境に Credential がないため固定データで代替しており、実際のセル書込みや実ポーリングは未検証です。Slack と Gmail 送信はノード設定のみ、LINE と Chatwork はローカルの受信先で本文を確認した段階で、実サービスへの到達は未検証です。n8n Cloud での動作、実在する銀行の CSV や通知メールも未検証です。実データでの検証はご自身の環境で、同梱の試運転手順に沿って行ってください。

## 向いていない場合

- JPY 以外の請求。他通貨の行は突合せず警告に出します。
- 特定の銀行との互換を求める場合。CSV の列の対応とメールの正規表現を自分で合わせる方式で、どの銀行とも互換を保証しません。
- 会計ソフトへの直接記帳。台帳は Google Sheets だけです。督促メール、消費税の判定もしません。
- 通帳画像や PDF の読み取り、1 通に複数の入金が並ぶメール。

## 安全面

- 秘密情報は n8n の Credential にだけ置きます。ワークフローの JSON にトークンや ID は含まれず、出荷前に秘密検出の grep で 0 件を確認しています。
- シートの読み書きノードに Continue On Fail は設定していません。失敗は実行の失敗として止まります。通知だけは全チャネルを試し、全チャネルが失敗したときに限り実行を失敗させます。
- Error Workflow を同梱しています。本体の Settings で指定し、本体と Error Workflow の両方を Publish すると、失敗したノード名・エラー・実行ログの URL が通知されます。
- 冪等です。入金ごとに決定的な `txn_id` を作り、台帳に既にあれば skip します。通知より先にシートへ書くため、通知が失敗しても再実行は全件 skip で済みます。
- 元の CSV やメールはシートに保存しません。

## 必要なもの

- n8n 2.x。2.40.5（セルフホスト）で構築・検証。組み込みノードのみで、n8n Cloud は 2.x 系で動く想定ですが、実機検証はしていません。Code ノードを使うため、セルフホストではタスクランナーが動く標準構成であること。
- Google アカウント。Google Sheets（台帳）、Google Drive（CSV の監視フォルダ）。Gmail は入金通知メールの取込かメール通知を使う場合のみ。n8n の Credential は Google Sheets OAuth2 / Google Drive OAuth2 / Gmail OAuth2。
- Google スプレッドシート 1 冊（`invoices` と `transactions` の 2 シート。`shared/sheets-schema.md` の手順で作成）。
- 銀行の入出金明細 CSV、または入金通知メール（どちらか一方でも可）。
- 任意：Slack（Bot User OAuth Token、`chat:write`）、LINE（Messaging API のチャネルアクセストークン）、Chatwork（API トークン）。

## よくある質問

**n8n Cloud で動きますか？**
組み込みノードだけで作り、Cloud で使えないノードは使っていないため、2.x 系の Cloud で動く想定です。ただし作者が検証したのはセルフホストの n8n 2.40.5 だけで、Cloud での実機検証はしていません。Cloud では Google の Credential に「Sign in with Google」が使えます。

**自分の銀行の CSV で動きますか？**
`CSV_MAPPING` で列見出し・見出し前の説明行数（`skip_rows`）・日付形式（`yyyy/MM/dd`、`yyyyMMdd`、`yyyy-MM-dd`）・文字コード（Shift_JIS 既定、UTF-8 BOM は自動判定）を合わせれば多くの入出金明細に対応できますが、特定銀行との互換は保証しません。金額のカンマ・`¥`・`円` は自動で除去します。設定例は `fixtures/csv_mapping.examples.json` にあります。
